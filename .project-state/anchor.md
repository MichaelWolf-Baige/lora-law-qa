## 4. 根因诊断：过度拒答

**现象**：103 题 87 题（84.5%）`n_citations=0`，其中 83 题直接「抱歉/无法」拒答。NHSR 90.6% 只对 21 条引用算，是**条件指标**，掩盖「根本不答」这个真失败。

**根因（已实测验证）**：不是「拒答数据太多」——RAFT 拒答负例仅 21.7%（符合 P=0.8 设计），train.jsonl 0 条拒答。真正的根因是**检索烂**，分两层：

1. **BM25 字级 bigram** 对口语化查询返回不相关条文（实测「老板不发工资」→「工资台账/代发工资」，唯独没有《劳动合同法》85 条）。
2. **RRF 融合 bug**（关键）：`_rrf_fusion` 旧实现按 `bm25_{idx}`/`dense_{rank}` 两套独立 id 各算各的，同一 chunk 永远合并不了分数，dense 的语义好结果被 BM25 不相关结果按 rank 挤出 top-k。（Dense 索引其实建好了，chroma 60311 文档，不是「关闭」。）
3. 推理思考模式默认开 → `</think>` 泄漏 + 输出方差大。

模型被 RAFT 教会「上下文不匹配就拒答」，检索给了不相关上下文 → 正确但过度地拒答。

**修复分层（对症，不矫枉过正）**：
- 检索侧（已修，commit 7af0e05）：`_rrf_fusion` 改按 content 对齐 + Dense 权重 > BM25；补口语→法言同义词。**检索质量质变**（5/6 口语化问题检索到相关法条）。
- 推理侧（已修）：软化 RAG 指令、空上下文兜底、`generation_config.enable_thinking=False`、剥离 `</think>`。
- **模型层残留拒答（需重训，交用户跑）**：检索对了仍拒（如「失业补偿金」检索到《失业保险条例》14条却拒答）——RAFT 补「检索到部分相关→给一般性说明」中间态，打破全有/全无两态。
